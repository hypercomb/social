# Anatomy, Context, Need — how a model outside the machine reads the hive

Status: DESIGN, agreed in conversation 2026-09-12. Nothing here is built yet
except where a section says so. Read `model-mediation-and-the-training-prompt.md`
first; this document is the half of it that concerns *what travels* to a model
and *how it comes back*, now that keyed third-party providers (OpenRouter) are
in the box.

## 0. The premise, stated once

Every API call is stateless. OpenRouter, Anthropic, OpenAI remember nothing
between requests. "Prompt caching" is a discount on a byte-identical prefix
that expires in minutes; it is not memory. Claude Code's context window is a
transcript the client resends. So Hypercomb resends too, and the whole design
is: **make the resent part identical, make the variable part small, and let
the model pull the rest.**

Signatures fit this exactly. Same sig, same bytes, same cache hit. Inflate is
a deterministic serialisation of any subtree. History is a lineage bag. The
hive already has every primitive this needs; this document only fixes their
roles.

## 1. Three things with three lifetimes

| Leg | What it is | Changes when | Travels as |
|---|---|---|---|
| **Anatomy** | What the hive *is*: layer protocol, inflate, pools, lineage bags, history rules, answering rules | the code changes | the system prompt, one sig-named file, cached |
| **Context** | Where the participant *is*: page, selection, recent turns, the subtree in view | every call | sigs in a small manifest; bodies pulled by tool inside a budget |
| **Need** | What is *asked*: the sentence, the tier, whether the caller can wait for an ask | every call | the `ModelNeed` the mediator already takes, plus the user turn |

Request order on the wire is always anatomy → tool roster → context manifest
→ transcript → need. Stable first, variable last. That ordering is what makes
prefix caching pay.

## 2. Anatomy — one file, two parts (patch to "build it from the census")

The census is **runtime and grant-filtered**: which behaviours exist and which
verbs this participant may be taught differ per machine and per grant. A file
built at build time cannot contain it. So the anatomy has two parts with two
lifetimes, and only the first is "the anatomy sig":

- **Static anatomy** — build-time artifact. The protocol: what a layer is, how
  a sig inflates (structural substitution, `{ $cycle }`, `{ $missing }`), what
  a pool of meaning is, what a lineage bag is and how to walk it (§6), how to
  answer (natural-language behaviour sentences, propose-don't-execute), the
  observation and action tools' contracts. Generated by a script from the
  doctrine docs and the tool schemas, signed, and given its own lineage bag at
  `sign('system:anatomy')` — a colon meaning, because it is a system pool no
  tile may name. Markers `0000`, `0001`, …; the max marker is the live
  anatomy. Roll back = advance a marker to an older sig. Never delete.
- **Doctrine** — part of the static anatomy, not a separate leg. Mechanics
  tell a model *how* to read; doctrine tells it *what it may propose*. A model
  that knows inflate but not "hide first, delete second" will propose a
  delete. The generator lifts these verbatim from their source documents so
  there is never a paraphrased second copy:
  - signatures are identity and composition; reference by sig, never inline
    (`signature-system.md`)
  - the name is the grammar; a molecule is `sign(name)`; a path is a route,
    never an address (`hypergraph-molecule-lineage.md`)
  - pools of meaning, no typed `__x__` folders, closed root vocabulary
    (`known-location-pools.md`)
  - data never heals: forward commits only, nothing deleted, hide first and
    delete second (`hypergraph-molecule-lineage.md`, this doc §6)
  - share resources, never copy; an artifact stands alone, relations are
    marks the members wear (`website-artifact-paradigm.md`)
  - derived caches are never truth (`optimize-phase.md`)
  - vocabulary: *tiles* to a participant, *cells* in code; *seed* is *cell*;
    behaviour sentences are proposed for the participant's Return, never
    executed by the model (`model-mediation-and-the-training-prompt.md`)
  Each rule names the document it came from. It will carry that document's
  sig once the doctrine docs ship as resources; until then a reader that
  wants the full argument asks the participant.

  BUILT 2026-09-12 (step 1): `hypercomb-essentials/scripts/build-anatomy.ts`
  runs from `prepare`, lifts the sections verbatim, emits
  `src/assistant/anatomy/anatomy.generated.ts`; `anatomy.service.ts`
  publishes `@hypercomb.social/Anatomy` (text + runtime-derived sig) and
  writes the text as a root resource on Store ready with `emit: false`. The
  chat sends it first, to every provider, with `cacheSystem: true`.
- **Live roster** — runtime, grant-filtered census: the behaviour list the
  `hypercombGrammarInstruction()` already derives. Small. Sent *after* the
  static anatomy as the tool roster, never folded into the anatomy sig.

The three existing copies collapse into this: `hypercomb-grammar.ts`'s
instruction becomes "static anatomy + live roster"; the bridge-listen
`SKILL.md` becomes a pointer that fetches the current anatomy by sig over the
bridge; the doctrine docs are the *source* the generator reads, not a fourth
copy.

## 3. Context — a manifest of sigs, bodies on demand

The request carries a **context manifest**, itself sig-addressed:

```json
{
  "anatomy":   "<static anatomy sig>",
  "page":      ["<layer sig>", "…"],
  "selected":  ["<layer sig>", "…"],
  "turns":     ["<turn sig>", "…"],
  "budget":    { "chars": 24000, "rounds": 3 }
}
```

Nothing inflated travels in the manifest. The model gets the roots and asks
for the rest through **one tool: `hive`** (Jaime, 2026-09-12: "the tool it
should ask for is the hive, to run queries and learn stuff"). Its argument is
a query sentence in the hive's own common tongue, read-only verbs only, the
verb list derived from the census and grant-filtered exactly like the action
grammar — a model is never taught a verb it may not use. The hive executes
the query inside the machine, against inflated content, and returns the
answer truncated to the remaining budget. The model never sees OPFS or a
path; it sees what the hive chose to return. Today's
`hypercombObservationTool` (3 rounds, 24 000 chars) is the seed of this door.

Verbs the anatomy lists for it (each is one query, same shape):

- read `<sig | route>` → the inflated subtree
- list `<sig | route>` → children as `{ name, sig }`
- history `<bagSig>` → markers with their sigs (§6)
- find `<name | pheromone>` → matching tiles as `{ name, sig }`
- summary `<sig>` → the compaction record for that input, if any (§5)

**Learning is recording.** Anything worth keeping goes back as content — a
note on a tile, a summary keyed by the sig it came from — and the next turn
or the next model pulls it with the same tool. That is how a stateless model
accumulates understanding. The same `hive` tool goes to every provider class;
only the gate (§4), the budget, and the grammar vary.

The budget is per conversation and per provider class, shown in the console
next to the switch in §4. It caps how many bytes can leave the machine, which
is the only privacy control that is mechanical rather than a promise.

## 4. The gate — the one real decision

Today the chat's rule is: a remote provider **never receives tree data or
action tools**; the observation and action tools go to the local model only.
That default stays. What changes is that a keyed provider can be *granted*:

- A per-provider switch in the providers console: **"may read the hive"**.
  Off by default. One-time hold semantics like the domain probe: turning it on
  is the participant choosing, and it sticks.
- Naming a remote model explicitly (`/gpt-5 …`) does **not** grant reading.
  Only the switch does. Explicit naming picks *who answers*; the switch decides
  *what they may see*. Keeping these separate is what stops a slip of the
  tongue from shipping a subtree to a vendor.
- Action tools follow the same switch. A provider that may read may also
  propose behaviour sentences; execution remains the participant's Return key
  (`search:prefill`), never the provider's.
- Peer-lent models never get the switch. A peer is someone else's machine.

Implementation is `hypercombActionProviderId()` growing from
`'local' | undefined` to "local, or any keyed provider whose switch is on."
Everything downstream already handles a provider id.

## 5. Compaction — a derived cache, but NOT minted in the optimize phase (patch)

A summary produced by a model is **not a pure derivation**: two runs give two
texts. The optimize-phase contract requires purity and no network, so
summaries must not be minted there. They are still derived-cache records in
every other sense — recomputable, wipe-safe, never load-bearing:

- Pool: `sign('compaction')` (colon-free system word, added to the registry
  the sanctioned way via `Store.poolSignature`; the reserved-name list does
  not grow — this is a pool, not a tile name).
- Key: `sign(inputSig + anatomySig + modelId)`. A summary depends on what was
  summarised, the anatomy that framed it, and who wrote it. Change any one and
  it is a miss, never a stale hit.
- Minted **on demand by the orchestrator** when `read()` would exceed the
  budget, using the mediator's cheapest able tier (`preferFree` means the
  local model does this when it is awake). Complete-or-absent.
- **Cross-compare** is two reads: `summary(oldSig)` and `summary(newSig)`, or a
  summary against the live subtree. Disagreement resolves in one direction:
  the subtree is truth, the summary is rederived. Summaries are never edited.

## 6. History — how a model with no memory remembers (anatomy §, verbatim intent)

Record-as-you-go, no monitor. Every turn writes its own marker at the moment
it happens; nothing watches from the side and nothing is reconstructed later.
A crash leaves the last complete marker intact. (A monitor would be a second
structure describing the first — the retired mirror pattern.)

- **A thread is a lineage bag.** One marker per turn. A turn resource holds:
  `anatomy` sig, the context manifest sig, the tool calls made (as sigs of
  their results), the answer sig, provider id and model id. The threads pool
  already stores turns by `contentSig`; this adds the four fields.
- **A bag is walked, never diffed.** Read the markers, inflate any one; two
  markers are two complete documents. There is no patch format to learn.
- **Replay is exact.** Any past turn can be re-sent against the anatomy it was
  sent with, because the anatomy sig is on the turn.
- **Nothing is rewritten.** New understanding is a new marker.

This section ships inside the static anatomy so every reader — keyed API,
local model, bridge — is taught the same way to look back.

## 7. Caching — the cheap part, once the shape is right

- `cacheSystem` exists on `LlmRequest` and is honoured only by the Anthropic
  adapter. The shared OpenAI shape gains the same flag: `cache_control` on the
  system block for OpenRouter's Anthropic routes (passed through), and nothing
  extra for OpenAI routes (automatic prefix caching). One edit in
  `openai-shape.ts`.
- The static anatomy is always sent with `cacheSystem: true`. It is the only
  thing stable enough to earn it.
- Transcript turns are sig-addressed (§6), so resent history is identical
  bytes and extends the cached prefix for free.
- **Size is not the rule; stability is.** The vendor cache keys on byte
  position, not on our sig, and the first send of a prefix is billed as a
  cache write at a premium. A large static anatomy is worth it because it is
  resent identically every call. A large subtree sent "in case" is a write
  that is never read back, and it moves with the participant so it breaks the
  prefix for everything after it. Big and stable goes in the prefix; variable
  stays small and is pulled. Our sigs deduplicate on our side only.

## 8. What was inconsistent, and how it resolved

| Said | Tension | Resolution |
|---|---|---|
| "send tools and info without inflating" / "freedom to read any way it likes" | push vs pull | manifest of sigs inline; bodies only through the tool, inside a budget |
| "APIs cache, I'm guessing" / "totally versioned and reversible" | vendor memory vs our history | caching is a prefix discount; versioning is ours via sigs; they align because same sig = same prefix |
| "leaving stuff behind or monitoring in real time — you decide" | two structures | record-as-you-go; no monitor |
| "remote never receives tree data" (code) vs "we're using OpenRouter now" | privacy rule vs new intent | per-provider opt-in switch; explicit naming still grants nothing |
| "build the anatomy from the census" | census is runtime + grant-filtered | static anatomy (build-time, sig, lineage) + live roster (runtime, after it) |
| "compaction in the optimize phase" | phase demands purity, no network | derived-cache pool, minted on demand by the orchestrator, keyed by input+anatomy+model |
| "the training prompt" ×3 copies | drift | one static anatomy; SKILL.md points at it; docs are its source |

## 9. Order of work

1. **Static anatomy generator** — script reads the doctrine docs + tool
   schemas, emits one file, signs it, advances `sign('system:anatomy')`.
   `hypercombGrammarInstruction()` sends it as the system prompt with
   `cacheSystem: true`, live roster after it.
2. **Turn fields** — `anatomy`, `manifest`, `toolCalls`, `answer` on the
   thread turn; the chat writes them as it goes. The `system:anatomy`
   lineage bag lands here too: `commitLayer` is for layers, so the bag needs
   the same marker primitive the thread bag uses, built once for both.
3. **The gate** — console switch, hold semantics, `hypercombActionProviderId`
   accepts a granted keyed provider; `history()` and `list()` join the
   observation tool.
4. **Cache flag** in `openai-shape.ts`.
5. **Compaction pool** and `summary()`.
6. Owed from the mediation doc, unchanged: derive `ModelNeed.tier`; an
   orchestration level.

Each step is verifiable on the dev shell without clearing OPFS: new sigs
appear, old ones remain, and a turn replayed against its recorded anatomy sig
produces the same request bytes.
