Your Claude Code subscription is the hive's AI

Connect Claude Code to a live hive. Ask from inside Hypercomb — the chat window or /opus … — and your own session, on the plan you already pay for, reads the hive and writes the answer back onto your tiles. No API key needed.

⬡ Hypercomb tab the renderer — your hive, opened with ?claudeBridge=1. Executes every operation against its own local storage.
◄── ws ──►
⬡ Broker localhost:2401 — a tiny relay. Interprets nothing, forwards everything, loopback-only by default.
◄── ws ──►
⬡ Claude Code the responder — a parked session (or a scheduled drain) that watches for questions, answers, and retires them.

A question typed in the hive becomes a durable ask record in your hive's own storage. Close the laptop mid-question — the ask survives and is answered when a responder next connects. Nothing leaves your machine.

Path A — the subscription loop

The hive walks you through this. The chat window's setup state is a guided checklist of these same steps — each checks itself off as it verifies (tab enabled, broker answering, first real answer landed). Open the chat and follow along; this page is the same path in full detail.

0

Prerequisites

Node.js ≥ 20.19 (nodejs.org), Claude Code with an active subscription, and the Hypercomb repository:

npm install -g @anthropic-ai/claude-code
git clone https://github.com/hypercomb/social.git hypercomb-social
cd hypercomb-social/src
npm install
npm run build:packages

Every command from here on runs from the repo's src/ directory.

1

Start the hive terminal A

npm run start:dev

Wait for the compile; the hive serves at http://localhost:4250.

2

Start the broker terminal B

npm run bridge
[bridge] listening on ws://127.0.0.1:2401
3

Open the hive tab — with the bridge flag

Open exactly one tab at:

http://localhost:4250/?claudeBridge=1

The broker's terminal prints [bridge] renderer connected.

Three rules that save an hour:
  • One tab only. The broker holds a single renderer slot, last-wins — a second bridge tab silently steals it.
  • Order matters once. Tab opened before the broker? Reload it — a tab that never connected doesn't retry.
  • Loopback only. The flag does nothing on a non-localhost origin, by design.
4

Verify the loop terminal C

npm run bridge:check

A tile listing means the whole loop works. no renderer connected means the broker is fine and the tab is the problem — wrong URL, stolen slot, or it needs a reload.

5

Park a listening session

In a Claude Code session opened at the repo root, say:

listen for hive asks

The session arms the watcher and answers asks the moment they land. Or park the raw watcher in a terminal (one JSON line per ask):

npm run bridge:watch
6

Ask from inside Hypercomb

In the hive command line:

/opus what is on this page?

/opus /sonnet /haiku /fable open the chat window on that model — type there like any chat. Select tiles first and the answer lands as a note on those tiles. /atomize asks for structure, /expand for new siblings, /organize for a grouping plan. Your parked session wakes, reads the tiles for context, and answers — live, no refresh.

7

Drive the hive from the terminal

The other direction — any terminal, including inside a Claude Code conversation, can operate the hive directly:

node scripts/bridge/bridge-cli.cjs list
node scripts/bridge/_bop.cjs '{"op":"note-add","segments":["my-tile"],"cell":"ideas","text":"hello from the terminal"}'

36 operations — read layers, add notes, write resources, add decorations — and {"op":"submit","text":"/website"} types into the hive command line itself, so anything you can do by hand, a script can do.

Optional modes

Unattended answering — no parked session

Schedule this every few minutes (Task Scheduler / cron). Zero pending asks costs nothing; pending asks spawn claude -p per model group, answer, and retire:

npm run bridge:drain

Remote answering session

The renderer tab must stay on the broker's machine — only the answering session can be remote, and only with a shared token. Without the token, remote senders are refused outright.

hive machine
BRIDGE_HOST=0.0.0.0 HYPERCOMB_BRIDGE_TOKEN=<shared-secret> npm run bridge
remote machine
BRIDGE_URL=ws://<hive-machine>:2401 HYPERCOMB_BRIDGE_TOKEN=<shared-secret> npm run bridge:watch

Path B: API keys instead of a subscription

Without Claude Code, the hive still answers two ways: a host relay (your hive host fields the ask with its own key and streams the answer — nothing to install), or a personal API key stored locally in your browser. Multi-provider keys — OpenAI, Gemini, Grok, DeepSeek, Mistral, local models — arrive with the provider picker page: every vendor as a branded hexagon, and picking one walks you through its key on first touch.

What the bridge is not

  • Not a cloud service. Every byte stays between your browser, a localhost relay, and a process you run.
  • Not Anthropic-specific as a protocol. An ask carries a model hint; any process that speaks WebSocket + JSON can be a responder. Adapters for other agent CLIs are on the roadmap.
  • Not keyed. Path A needs no API key — the subscription you already have is the whole engine.
