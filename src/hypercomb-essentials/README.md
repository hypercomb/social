# Hypercomb Essentials

`@hypercomb/essentials` is Hypercomb's first-party capability library. Its
source tree is organized by capability rather than by deployment host:

- `assistant/`, `commands/`, `navigation/`, and `presentation/` provide the
  primary interaction and rendering system.
- `history/`, `sequence/`, `sharing/`, and `substrate/` provide authored-state
  and collaboration behavior.
- The remaining top-level folders are similarly scoped capabilities.
- Domain-shaped folders are reserved for separately owned capability packs,
  not for the Essentials package itself.

Import capabilities through package-qualified subpaths such as
`@hypercomb/essentials/presentation/tiles`. The package build emits those same
names as dependency aliases.

Some IoC keys and bee namespaces still begin with
`@diamondcoreprocessor.com/` or `diamondcoreprocessor.com`. These are runtime
compatibility identifiers used by existing hives, extensions, and deployed
content; they are not source-tree namespaces. Migrate them separately through
aliases rather than changing them as part of a filesystem move.

Barrel files, `essentials-keys.ts`, `side-effects.ts`, and `preload-effects.ts`
are generated by `npm run prepare` and should not be edited manually.
